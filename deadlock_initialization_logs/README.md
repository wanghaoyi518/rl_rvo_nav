# 死锁初始化日志说明

本目录包含死锁模块初始化时的详细日志信息，用于分析和调试死锁检测与解决过程。

## 日志文件类型

### 1. 死锁激活日志 (`deadlock_init_t{timestep}_agents{N}_{timestamp}.txt`)

记录死锁检测激活时的详细信息，包括：

- **基本信息**: 时间步、涉及智能体、死锁组
- **环境信息**: 世界大小、障碍物数量、机器人数量
- **智能体状态**: 位置、速度、目标、到目标距离
- **检测器信息**: 触发类型、平均速度、邻居数量、速度缓冲区大小
- **邻居信息**: 邻居智能体的距离和速度
- **死锁检测配置**: 所有检测参数
- **Waypoint信息**: 每个智能体的路径点序列
- **触发条件分析**: 详细分析死锁触发的原因

### 2. MAPF会话初始化日志 (`mapf_init_session_{session_id}_t{timestep}_{timestamp}.txt`)

记录MAPF（多智能体路径规划）会话初始化时的详细信息，包括：

- **会话信息**: 会话ID、时间步、参与智能体
- **BBox信息**: 边界框坐标、尺寸、面积
- **子图信息**: 网格大小、分辨率、物理尺寸
- **栅格地图详细信息**: 
  - 地图统计：总格子数、可通行格子数、障碍物格子数及比例
  - 地图可视化：完整的栅格地图内容（0=可通行，1=障碍物）
  - 智能体位置标记：每个智能体起点和终点在地图中的位置及可通行性
  - 路径分析：路径上每个格子的状态，包括障碍物检测
  - 连通性分析：起点和终点的可通行性检查
- **起点信息**: 每个智能体的起始网格坐标和世界坐标
- **目标点信息**: 每个智能体的目标网格坐标、世界坐标、最近的waypoint
- **路径信息**: 生成的路径长度、起点、终点、距离
- **Actor信息**: MAPF算法中的智能体表示
- **执行器信息**: 路径执行器的准备状态

## 栅格地图信息详解

### 地图统计
- **总格子数**: 栅格地图的总单元格数量
- **可通行格子**: 值为0的格子，表示可以移动的区域
- **障碍物格子**: 值为1的格子，表示静态障碍物
- **比例分析**: 可通行区域和障碍物区域占总地图的百分比

### 地图可视化
- **格式**: 二维数组表示，每行代表地图的一行
- **坐标系统**: 左上角为原点(0,0)，向下为i轴，向右为j轴
- **显示限制**: 如果地图过大（>20x20），只显示左上角部分
- **示例**:
  ```
  0 0 0 0  (第0行：全部可通行)
  0 1 1 0  (第1行：中间有障碍物)
  0 1 1 0  (第2行：中间有障碍物)
  0 0 0 0  (第3行：全部可通行)
  ```

### 智能体位置标记
- **局部坐标**: 相对于子图左上角的坐标
- **格子值**: 该位置的栅格值（0或1）
- **可通行性**: 判断该位置是否可通行
- **边界检查**: 检查位置是否在地图范围内

### 路径分析
- **逐点检查**: 分析路径上每个格子的状态
- **障碍物检测**: 识别路径上的障碍物
- **边界检查**: 检查路径点是否超出地图范围
- **统计汇总**: 统计路径上的可通行、障碍物、边界外格子数量

### 连通性分析
- **起点检查**: 验证智能体起始位置的可通行性
- **终点检查**: 验证智能体目标位置的可通行性
- **警告提示**: 当起点或终点不可通行时发出警告

## 日志文件命名规则

- **死锁激活日志**: `deadlock_init_t{timestep}_agents{N}_{timestamp}.txt`
  - `timestep`: 死锁激活的时间步
  - `N`: 涉及智能体数量
  - `timestamp`: 日志生成时间戳

- **MAPF会话日志**: `mapf_init_session_{session_id}_t{timestep}_{timestamp}.txt`
  - `session_id`: MAPF会话ID
  - `timestep`: 会话创建时间步
  - `timestamp`: 日志生成时间戳

## 使用场景

### 1. 死锁检测调试
通过分析死锁激活日志，可以：
- 验证死锁检测的触发条件是否正确
- 检查智能体状态是否符合死锁特征
- 分析邻居关系和速度模式

### 2. 目标点选择分析
通过分析MAPF会话日志，可以：
- 验证BBox计算是否合理
- 检查目标点与waypoint的距离
- 分析路径规划的质量

### 3. 栅格地图问题诊断
通过分析栅格地图信息，可以：
- **起点/终点问题**: 检查智能体是否被放置在障碍物上
- **路径规划问题**: 识别路径上的障碍物冲突
- **地图构建问题**: 验证子图构建的正确性
- **连通性问题**: 确认起点到终点的可达性

### 4. 性能优化
通过对比不同场景的日志，可以：
- 识别死锁检测的瓶颈
- 优化MAPF算法的参数
- 改进目标点选择策略
- 调整栅格地图的分辨率和大小

## 关键指标

### 死锁检测指标
- **平均速度**: 应低于阈值（默认0.1 m/s）
- **邻居数量**: 应满足最小要求（默认2个）
- **连续满足步数**: 应达到激活迟滞要求（默认3步）

### MAPF指标
- **BBox面积**: 应适中，过大影响效率，过小可能导致目标点选择失败
- **目标点距离**: 与waypoint的距离应尽可能小
- **路径长度**: 应合理，避免过长或过短的路径

### 栅格地图指标
- **可通行比例**: 应大于50%，确保有足够的移动空间
- **起点可通行性**: 所有智能体起点必须可通行
- **终点可通行性**: 所有智能体终点必须可通行
- **路径无障碍**: 生成的路径不应包含障碍物

## 示例分析

### 问题场景
从示例日志可以看出：
1. **目标点距离问题**: Agent 0的目标点距离waypoint 2.5米，说明目标点选择不够优化
2. **BBox大小**: 3.67×3.35米，在狭窄走廊中可能过大
3. **触发条件**: 两个智能体都满足速度条件，但邻居数量不足，需要检查邻居检测逻辑
4. **栅格地图问题**: Agent 0的起点和终点都在障碍物上，这是严重的问题

### 改进建议
1. **优化目标点选择**: 减少目标点与waypoint的距离
2. **调整BBox计算**: 根据环境特征动态调整边界框
3. **改进邻居检测**: 确保邻居检测的准确性
4. **修复栅格地图**: 确保起点和终点选择在可通行区域

## 注意事项

1. **日志文件大小**: 日志文件可能较大，建议定期清理
2. **时间戳**: 确保系统时间准确，便于日志分析
3. **编码格式**: 日志文件使用UTF-8编码，支持中文注释
4. **错误处理**: 日志生成过程中的错误会被捕获并输出到控制台
5. **栅格地图显示**: 大型地图会被截断显示，完整信息仍保存在日志中
